# 内存模型与原子操作

一句话：`atomic` 解决多线程下的数据竞争，提供原子性、可见性、有序性。

## 数据竞争（data race）
两个线程无同步地读写同一变量（至少一写）→ 未定义行为。
`counter++` 是三步：读 → +1 → 写回，不是原子的。

## atomic 三个作用
| 作用 | 含义 |
|------|------|
| 原子性 | 读改写不可分割 |
| 可见性 | 写后其他线程立刻可见 |
| 有序性 | 防止编译器/CPU 乱序重排 |

## memory_order 三种
| 级别 | 保证 | 场景 |
|------|------|------|
| seq_cst（默认） | 最强全局顺序 | 默认最安全 |
| acquire / release | 配对，约束一对 | 生产者消费者 |
| relaxed | 只保证原子性 | 只计数 |

## 面试高频题
**Q: acquire/release 为什么配对？**
A: release = "前面的写都准备好了"，acquire = "看到发布后，前面的写都可见"。配对才能保证普通变量的可见性。

**Q: volatile 能代替 atomic 吗？**
A: 不能。volatile 不保证原子性，也不阻止重排，用途完全不同（volatile 用于硬件寄存器等）。
