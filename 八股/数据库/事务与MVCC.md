# 事务与 MVCC

一句话：事务保证 ACID，MVCC 用版本链实现快照读、减少锁冲突。

## ACID 四大特性
| 特性 | 含义 |
|------|------|
| 原子性 Atomicity | 事务要么全成功要么全回滚 |
| 一致性 Consistency | 事务前后数据满足约束 |
| 隔离性 Isolation | 事务间互不干扰 |
| 持久性 Durability | 提交后永久保存（redo log） |

## 隔离级别（从低到高）
| 级别 | 解决 |
|------|------|
| 读未提交 | 最弱，脏读 |
| 读已提交 | 解决脏读，有不可重复读 |
| 可重复读（MySQL 默认） | 解决不可重复读，有幻读（MySQL 用 MVCC+间隙锁解决） |
| 串行化 | 最强，性能最差 |

## MVCC（多版本并发控制）
- 每行有隐藏列：事务 ID、回滚指针
- 版本链：undo log 记录历史版本
- 快照读：读事务开始时的版本，不加锁
- 当前读：加锁读最新版本（update/delete）

## 面试高频题
**Q: 事务四大特性？**
A: 原子性、一致性、隔离性、持久性。

**Q: MVCC 是什么？**
A: 通过 undo log 版本链，每个事务读自己的快照，不加锁，实现高并发读。

**Q: redo log 和 undo log 区别？**
A: redo 保证持久性（崩溃恢复，记录"做了什么"）；undo 保证原子性/MVCC（回滚，记录"改之前的旧值"）。
