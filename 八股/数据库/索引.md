# 数据库索引

一句话：索引加速查询，MySQL InnoDB 用 B+ 树。

## 为什么用 B+ 树而不是红黑树/哈希
- B+ 树是多叉树，树矮，**减少磁盘 IO 次数**（磁盘 IO 是瓶颈）
- 叶子节点用链表串起来，**支持范围查询**
- 哈希 O(1) 但不支持范围、无序

## B+ 树特点
- 非叶子节点只存索引，叶子节点存全部数据（聚簇）或主键（非聚簇）
- 所有数据都在叶子节点，叶子有序链表连接

## 索引类型
| 类型 | 说明 |
|------|------|
| 聚簇索引 | 叶子存整行数据，一个表只能一个（主键） |
| 非聚簇索引 | 叶子存主键，回表查整行 |
| 覆盖索引 | 索引包含查询所需全部列，不用回表 |

## 最左前缀原则
联合索引 (a, b, c) 只能用于 a、a+b、a+b+c 的查询，跳过 a 用 b 则索引失效。

## 面试高频题
**Q: 为什么 B+ 树？**
A: 树矮减少磁盘 IO；叶子链表支持范围查询。

**Q: 索引失效场景？**
A: 最左前缀不满足、对索引列用函数/运算、like '%xx' 前导模糊、类型隐式转换等。

**Q: 聚簇 vs 非聚簇？**
A: 聚簇叶子存整行（一个表一个）；非聚簇叶子存主键，查整行要回表。
