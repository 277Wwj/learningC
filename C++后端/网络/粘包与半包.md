# 粘包与半包

一句话：[[TCP]] 是字节流、没有消息边界，所以 send 几次和 recv 几次没有对应关系。

## 是什么
- **粘包**：多条消息粘在一起到达
- **半包**：一条消息被拆成多段到达

## 为什么（根本原因）
TCP 只保证字节顺序和可靠，不保证"一次 send = 一次 recv"。
（类比：水管流水，下游可能一次接到两杯水，也可能一杯水分两次接到）

## 怎么解决
用 [[Buffer]] 攒字节，再用 [[消息边界]] 的三种方法定边界。

## 关联
- [[keep-alive]] 会加剧粘包（一个连接连续多个请求）
- [[LT与ET]] 决定 recv 的循环读取方式
