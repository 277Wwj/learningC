# 线程池

一句话：预先开好 N 个线程 + 一个任务队列，提交任务就丢进队列，worker 抢着执行——避免每个任务都创建/销毁线程。

## 核心组成
- 任务队列：`queue<function<void()>>`
- worker 线程：循环 `cv.wait` 等任务，拿到就执行
- `packaged_task` + `future`：提交任务时能拿到返回值

## 关键点
- `enqueue` 用 `make_shared<packaged_task>` 包一层，因为 packaged_task 只能 move 不能 copy。
- 通知用 [[condition_variable]]：`cv.notify_one()` 唤醒一个 worker 抢任务。
- 任务为空时 worker 睡眠，析构时再唤醒退出。

## 经典死锁（我的代码）
析构函数**持锁 join**：worker 被唤醒后要重新拿锁才能退出循环，
但主线程持锁等 join → 双向等待。
**解决：join 移出锁外。** 详见 [[mutex与死锁]]。
